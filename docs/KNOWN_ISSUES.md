## SEC-001：超时后执行可能继续并产生副作用

- 严重程度：高；状态：OPEN / DEFERRED（按用户决定暂缓修复）。
- 受测分支：`feat/security-retry-foundation`。
- 受测提交：`a514667a092f54b1b83d200461b91fed2c597698`。
- 环境：Windows 10.0.26200、Python 3.13.2、Docker 29.7.2、Compose 5.4.0、agent-sandbox 0.0.30。
- 镜像：`enterprise-public-cn-beijing.cr.volces.com/vefaas-public/all-in-one-sandbox:1.11.0`。
- 实际镜像 ID：`sha256:6328d7fd2f0ff0b4c147c3d05b3df1ce331f4a482eb6e550ecd64ed1fcf906e7`。

### 复现与证据

运行 `python -m demo.security_smoke`，退出码为 1（确定失败，不是未验证）。资源配额、文件读写、越界路径拒绝、独立会话四项通过。

`timeout=1`、`sleep(6)` 后写文件的探针约 6.7 秒返回，状态为 error，文件已写入；独立复测同样出现延迟文件。`timeout=2`、`sleep(8)` 的探针约 7.6 秒返回 error，该次会话清理赶在写入前终止执行，不能据此保证超时终止可靠。

报告中的服务端定位：`app/services/jupyter.py::_execute_code_sync` 等待 IOPub 消息超时抛出 `queue.Empty`，异常文本匹配未识别为 timeout；随后最多等待 5 秒 shell reply，且没有主动中断内核。客户端 finally 删除会话可能晚于副作用发生。该根因定位来自桌面报告，跨主机复现仍待补充。

### 影响与暂行边界

- 不阻断任务持久化、事件轨迹、工具注册、Memory、Evaluation 等独立模块开发。
- 依赖真实沙箱的文档产物测试可以继续，但不能据此宣称超时安全验收通过。
- 当前不能承诺超时后代码或派生执行已停止；返回失败也不代表没有副作用。
- 超时或执行结果不确定的工具不得自动重放；任务终止状态与实际进程停止必须分别记录。
- 保留现有烟测断言，不延长超时、不忽略延迟文件、不将失败改为跳过来通过验收。
- 第一批安全验收保持 IN_PROGRESS；最终“实现并验证能力 ≥ 简历承诺”的标准不变。此问题必须在最终验收前关闭。

### 后续修复与关闭标准

1. 在 Linux 补充同镜像复测，保存版本、命令和退出码；无需等待此项再开发独立模块。
2. 选择可验证的执行终止方案，例如受控服务端修改或具有可靠终止能力的隔离执行后端；不能只修正返回状态。
3. 明确执行截止时间与有限清理窗口，终止失败须显式标记执行不确定，禁止继续复用受影响执行环境。
4. 验证超时状态正确、截止后执行被终止、等待超过原延迟后没有新文件，并补充派生进程与清理失败场景。
5. 原始真实烟测与回归通过，记录新提交和镜像 ID 后再关闭问题。
