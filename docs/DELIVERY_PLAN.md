# 交付标准与简历对标计划

用户已确认：最终实现并验证的能力 ≥ 简历承诺；计划覆盖全部承诺，并包含 Memory、Evaluation 等增强。按模块交付，不把配置、离线 fake 或未运行的脚本写成真机验证。

## 当前优先级与验收阻碍

按用户决定，真实 Docker 超时终止失败暂缓修复，继续第 2 至第 5 批独立模块开发。失败证据、影响和关闭标准见 [已知问题](KNOWN_ISSUES.md)。第一批安全验收仍为 IN_PROGRESS；最终验收必须关闭 SEC-001，不放宽真实烟测。

## 五批路线

| 批次 | 必须交付 | 验收 |
| --- | --- | --- |
| 1 Retry + Security | 分类修正、工具重试安全声明、Schema 校验、白名单、工作区路径、报告对象前缀、拒绝审计、默认与上限超时、会话清理、CPU/内存/PID 配额 | 离线回归和演示；真实容器验证单独记录 |
| 2 任务轨迹与异步执行 | 持久化任务/步骤/计划/调用/重试/终止事件，关联 ID、逐次写入、并发上限、任务总时限与工具预算、终态收敛 | 重启可查轨迹，异常不遗留 RUNNING；不把线程超时冒充代码停止 |
| 3 文档与产物闭环 | 任务输入装载、任务专属目录及对象前缀、产物元数据、存在/非空/业务校验、有限恢复 | CSV/XLSX 真机产物正确，URL 过期和匿名访问验证 |
| 4 Memory | 短期上下文预算及大结果引用，长期脱敏摘要检索 | tool_call_id 消息配对完整，长任务和历史复用可验证 |
| 5 Evaluation 与补充能力 | LLM usage、耗时、成功率/产物达标率/重试率，固定评估集；MCP 文档解析，持久化队列与 worker 增量接入 | 真实运行指标、真实文档解析、队列故障恢复分别验证 |

## 简历承诺的证据清单

- 三层架构与 Agent Loop：Planner 结构化计划，Executor 工具结果回传，Orchestrator 状态编排；非法参数也有反馈。
- 终止控制：最大轮数已有；任务总时限、工具预算、终止原因在批次 2；产物成功判据在批次 3。
- 两级任务模型与异步：现有状态机和后台线程；“完整轨迹留存”需批次 2 持久化完成。
- 可插拔工具：注册后模型可见 Schema，无需改 Executor；不承诺目录扫描、热加载或远程发现。
- 安全执行：容器隔离 + 本批权限/超时/配额；共享容器不是恶意多租户隔离。任务专属路径在批次 3 落地。
- 对象存储：实际为 MinIO/S3 兼容后端，非已验证的阿里云 OSS；URL 是有有效期的 bearer 凭证。
- 异常恢复：只对声明可安全重放的工具重试瞬态错误；不保证任意 Python exactly-once。

每批附中文 Design Note、运行命令、实际结果和未验证边界。Memory/Evaluation 不替代上述简历必达项。Multi-Agent、并行工具、多租户和生产横向扩展暂不承诺。

## 可学习性约束与本轮增量

先以 Python 标准库 SQLite 完成任务持久化，沿用既有接口；异步入口使用信号量限制并发。无需新增数据库服务或队列。每次增加能力都提供设计说明和针对性测试。详见 [任务持久化学习说明](design/11_task_persistence.md)。本轮完成持久化、生命周期记录、计划保存及并发入口上限；总时限、工具预算、异常中断恢复仍待实现，第二批尚未整体完成。
